# Planeación generation repairs

The old workflow requested the entire multi-page main document in one model response, followed by its subplans. A response stopped at its token limit was logged but still returned to callers. The fallback used JSON mode even for plain-text section rewriting, and neither valid JSON nor one long subplan paragraph proved that every requested section existed.

The generator now creates the main development and routines separately, then generates evaluation using the actual development as context. School-specific sections are generated in small batches and restored to the uploaded format's order. The group schedule and selected official Contenido/PDA table are copied from known data. Only failed fields are retried; unexpected model keys cannot overwrite a successful part. A complete bundle is saved only after validation, using a conditional update to protect edits made during generation.

Additional explicit units are no longer removed because they share the Proyecto or Centro de Interés methodology, or silently capped at three. Subplans must contain every requested teaching stage, substantive evaluation, and recognized official content. The individual subplan endpoint loads the full period, including later weeks and number ranges, and passes the official grounding to the model.

Provider completion status is checked before accepting output. JSON and plain-text tasks use the corresponding fallback format. Calls have explicit time limits, no hidden SDK retries, and share a deadline within full-document generation. Provider outages produce an availability error; they are not presented as a successful document.

Saved warnings are also recomputed from normalized current content, including after manual edits, chat edits and section regeneration. Teachers can complete an empty narrative section directly from its warning without replacing the rest of the document.

## Verification and remaining limits

Automated coverage exercises provider truncation, malformed JSON, fallback outage, plain-text fallback, missing fields, missing methodology stages, custom-section order, additional units, stale warnings, and concurrent edits. Run `npm test`, `npm run typecheck`, and `npm run build`.

The opt-in command `PLANNER_LIVE_SMOKE=1 npx vitest run lib/planner/generation.live.test.ts --reporter=verbose` generates a fictional main plan plus Letters and Números with the locally configured providers. It does not access teacher records or save a plan to the database. The live attempt on October 6, 2026 did not complete: the primary provider returned HTTP 403 “Request not allowed,” and fallback requests timed out. This establishes an access/connectivity problem in this test environment, not proof that production uses the same configuration or has the same failure.

At the initial review, the changes had not been deployed. The required migrations are `090_fortnight_format_template.sql` (exact format selection) and `091_atomic_plan_document_save.sql` (atomic document saves) (applied on October 8 after authentication was restored). The save function runs with the caller's privileges, retains RLS, and checks teacher ownership. Comparing documents inside this function avoids putting large JSON documents in a URL. A successful provider-backed generation and a production user-flow check remain necessary before declaring the full workflow verified in production.

## October 8 follow-up: sources, preparation and homework

Read-only checks against the configured database found seven saved plans, five carrying stored warnings. All seven already contained substantial initial and routine activities (685–1,353 and 777–1,696 characters respectively). Two of five saved template profiles contained section excerpts but no full example text. There were 33 materials, two shared links, and no recorded game attempts. These counts describe the configured database at inspection time; no teacher data was changed. The `fortnights.format_template_id` column was confirmed missing, and was added by migration 090 during the authenticated release check.

Additional defects corrected:

- Preparation previously awaited AI-based learning refresh and unbounded curriculum/embedding calls before opening the progress stream. Progress now starts before those pedagogical steps; generation uses cached learned preferences, bounded embedding requests, and the planner transport with fallback for curriculum selection. No empty selection is silently accepted.
- The official-content normalizer previously returned invented model output unchanged when _nothing_ matched. It now returns no accepted rows. The main project uses its own unit's selected curriculum; custom units preserve their own official content and selected cross-grade PDAs. Taller activities receive the same curriculum that is placed in their table.
- Monthly plans looked for a nonexistent `mes` template type instead of `quincena`. They now resolve the uploaded quincena format correctly.
- DOCX extraction discarded everything after 16,000 characters; storage and generation applied further cuts. Accepted examples now retain the complete text, up to an explicit 60,000-character limit. PDF/image extraction must also return the full anonymized transcription; a token-limit stop is rejected, even if the JSON parses. School headings are protected from the conservative name scrub. Nested methodology headings are extracted separately from top-level sections.
- The selected example, its structure and layout take priority over older learned plans. A shared template-context builder passes this same authority order to generation, subplans and section repairs. Legacy formats that have only fragments are identified in Configuración; the original source must be uploaded again because it was not retained by the old ingestion path.
- Accepted attachment text is no longer silently shortened to the beginning of each file. The shared cached context includes the complete available attachment text for all units, with explicit per-file/bundle limits. Regenerating a subplan or section receives these sources too. Oversized or truncated uploads report an error instead of claiming successful complete extraction. Old attachment records already shortened by the previous uploader also require re-upload to recover the omitted source text.
- Concurrent link creation now updates a material only while its token is null, then reads the winning permanent link. Children still choose a nickname/avatar without signing in. Completed attempts carry a UUID and are queued on the device until saved; reloading or reconnecting retries the same attempt. The API uses the existing `game_plays.id` primary key for idempotency and verifies teacher/profile/material ownership. Changing players starts a fresh game, and duplicate completion callbacks cannot double-count one run.

Teacher workflow: open a playable material, use **Enviar como tarea a casa → Crear enlace del juego**, copy or share via WhatsApp, and optionally set the completion target. **Probar como alumno** opens the public game. Children choose an avatar and nickname, play, and see confirmation that their progress was saved. The teacher views attempts on the material and can associate the child's displayed code/profile with a roster student. Playing via the explicit “sin guardar” option does not record progress.

Validation covers concurrent share requests, anonymous attempt saving, rejected cross-teacher profiles, lost-response retries, reload recovery, repeated completion callbacks, the end of long examples/attachments, truncated visual extraction, per-unit PDAs, and preparation streaming before curriculum selection finishes. No real emails were sent and no real student attempts were created. Model-list probes on October 8 still failed locally (Anthropic HTTP 403; OpenAI connectivity failure). Successful real-provider generation remains unverified. Exact reproduction of arbitrary merged Word tables or scanned page geometry is not promised by the semantic document renderer; supported structure, section order, typography, page orientation and margins are preserved.

Final local checks on October 8: **409 automated tests passed**, one opt-in live-provider test skipped; the production build passed compilation, lint and type validation. On an isolated production server at port 3107, both existing shared game URLs returned HTTP 200 without a login redirect. A fresh headless Chrome profile reached the nickname/avatar screen, selected the explicit guest-play option and started the shared flashcards game. This browser check did not create a player, save an attempt, send mail, or modify the configured database. Anonymous persistence and teacher scoping were exercised in API/component regression tests; a deployed, real-device round trip still needs verification after rollout.

## Production release review

Creation now writes the complete draft in one atomic insert. The main prompt and completeness validator share the same heading resolution, preserving the distinction between an explicit methodology and an automatic fallback. Game and email links also reject localhost or malformed configured origins when generating a public link.
